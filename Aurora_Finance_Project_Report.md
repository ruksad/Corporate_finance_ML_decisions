# Module 1 — Corporate Project Funding

**Notebook:** `Step1_corporateFinance_project_funding.ipynb`

---

## 1.1 Problem Statement / Objective

Aurora Finance's investment committee must allocate limited capital across a pool of internal projects. The challenge is two-fold:

1. **Task 1 — Cash Flow Forecasting:** Predict the total 3-year cash flow generated by each project so the committee can estimate financial value.
2. **Task 2 — Success Classification:** Predict the probability that a project will succeed (positive NPV) and score its risk level.
3. **Task 3 — Capital Allocation:** Rank and recommend projects based on expected economic value (EV) and risk-adjusted return.

---

## 1.2 Dataset Description

| Attribute | Details |
|---|---|
| **Source file** | `sample_data/corporate_projects.csv` |
| **Rows** | 50 projects |
| **Key raw columns** | `Project_ID`, `Department`, `Investment_Cost`, `Expected_Cashflow_Year1/2/3`, `Project_Risk` (Low/Medium/High), `Historical_ROI`, `Market_Growth` |
| **Target (Task 1)** | `Total_Cashflow` = sum of 3-year cashflows |
| **Target (Task 2)** | Binary success label derived from NPV > 0 |

**Departmental breakdown:** Finance, Marketing, Operations, Technology  
**Risk distribution:** Low / Medium / High (roughly balanced)

---

## 1.3 Methodology / Approach

**Task 1 — Regression (Cash Flow Forecasting):**
- n=50 is a small dataset, so feature count was deliberately capped at 4 to maintain a samples-to-features ratio ≥ 10 (avoiding overfitting).
- Three models compared using Leave-One-Out Cross-Validation (LOOCV), which is the correct CV strategy for very small datasets.
- A LOOCV-correct naive baseline (predicting the training fold mean for each left-out sample) was used as a benchmark.

**Task 2 — Classification (Project Success Probability):**
- Five domain-driven features derived from financial theory replaced 12 raw input columns, improving the sample-to-feature ratio from 1:4 to 1:10.
- Three classifiers compared using 5-fold stratified CV with AUC as the primary metric.

---

## 1.4 Data Preprocessing Steps

| Step | Description |
|---|---|
| **Target construction** | `Total_Cashflow = CF_Y1 + CF_Y2 + CF_Y3`; source columns dropped immediately to prevent leakage |
| **Risk encoding** | `Project_Risk` mapped ordinally: Low=1, Medium=2, High=3 |
| **Interaction feature** | `Market_Adjusted_ROI = Historical_ROI × (1 + Market_Growth)` — captures ROI amplified by sector conditions |
| **NPV calculation** | Discounted at 10%; used as intermediate input to engineered features |
| **IRR computation** | Newton-Raphson iteration on 3-year cashflow stream |
| **Feature scaling** | `StandardScaler` inside Pipeline (fit only on training fold — no leakage) |

---

## 1.5 Model Implementation / Details

### Task 1 — Regression Models

| Model | Key Parameters |
|---|---|
| Ridge Regression (RidgeCV) | α searched over log-space [0.01, 10,000], 5-fold inner CV |
| KNN Regression | k=5, distance-weighted |
| Random Forest Regressor | 300 trees, max_depth=3, min_samples_leaf=5, max_features=0.6 |

**Features used:** `Investment_Cost`, `Risk_Score`, `Historical_ROI`, `Market_Adjusted_ROI`  
**Validation:** Leave-One-Out CV (50 folds, one project left out per fold)

### Task 2 — Classification Features (Domain-Driven)

| Feature | Financial Meaning |
|---|---|
| F1 — Profitability Index | NPV / Investment_Cost — return per dollar invested |
| F2 — CF Trajectory | (CF_Y3 − CF_Y1) / |CF_Y1| — growing vs declining cash flows |
| F3 — IRR Spread | IRR − 10% hurdle rate — excess return over minimum threshold |
| F4 — Risk-Adjusted Profitability | Profitability Index / Risk_Num — combines return quality and risk |
| F5 — Capital Efficiency | NPV / (Investment_Cost × Duration) — value per dollar per year |

**Models compared:** Logistic Regression, Random Forest Classifier, SVM  
**Validation:** 5-fold Stratified CV | **Primary metric:** AUC-ROC

## 1.6 Results and Observations

### Task 1 — Regression Results (LOOCV)

| Model | MAE | RMSE | R² | vs Baseline |
|---|---|---|---|---|
| Naive Baseline | ~$3.9M | — | 0.0 | — |

---

## 1.7 Conclusion / Future Scope

**Conclusion:** Ridge regression is the recommended model for cash flow forecasting on this small dataset — it is regularised, interpretable, and degrades gracefully when feature signal is weak. The domain-driven classification features outperform raw column encoding.

**Future Scope:**
- With more historical project data (n > 200), XGBoost or ensemble stacking would likely outperform Ridge.
- Time-series decomposition of cashflow trajectories could improve multi-year forecasts.
- Bayesian uncertainty quantification could replace point predictions with confidence intervals for the investment committee.

# Module 2 — Banking: Loan Portfolio & Fraud Detection

## 2.1 Problem Statement / Objective

Aurora Finance's banking division must:

1. **Task 1 — Loan Risk Assessment:** Predict each borrower's Probability of Default (PD) and classify them into risk tiers (Low / Medium / High).
2. **Task 2 — Fraud Detection:** Flag suspicious transactions using supervised and unsupervised models, producing a tiered alert system.
3. **Task 3 — Lending Decision Engine:** Combine Tasks 1 & 2 outputs to produce a final lending decision (APPROVE / CONDITIONAL / REJECT) with monitoring strategy and adjusted interest rate for each loan.

---

| **Class imbalance** | 191 legitimate (95.5%) vs 9 fraud (4.5%) |

---

## 2.3 Methodology / Approach

### Task 1 — Three-Stage Pipeline

```
Stage 1: PD Regression (Ridge vs Lasso, LOOCV)
              ↓
         PD_predicted column appended to loan data
              ↓
Stage 2: Risk Scoring (weighted composite score)
              ↓
         Risk_Class labels (Low / Medium / High)
              ↓
         Classification (Logistic Regression vs Decision Tree)
```

### Task 2 — Ensemble Fraud Detection

- **Logistic Regression (Supervised):** Trained on SMOTE-oversampled data to address class imbalance. Threshold optimised using F2-score (β=2) on the Precision-Recall curve — penalising missed fraud more than false positives.
- **Isolation Forest (Unsupervised):** Anomaly detection trained without labels. Anomaly scores converted to pseudo-probabilities via min-max scaling.
- **Ensemble Alerting:** RED = both models flag; AMBER = either model flags.

### Task 3 — Lending Decision Engine

A rule-based engine that merges risk class and fraud signals:
- `Low Risk + No Fraud` → **APPROVE**
- `Medium Risk` → **APPROVE — Standard Monitoring**
- `High Risk` → **REJECT — High Risk**
- `Any fraud signal` → **REJECT — Fraud Alert**
- `Past_Default = 1` → **REJECT — Prior Default**

Adjusted interest rates and monitoring cadences are assigned per tier.

---

| Step | Details |

# Module 3 — Financial Markets: Portfolio Strategy

**Notebook:** `Step3_financial_markets_investment_strategies.ipynb`

---

## 3.1 Problem Statement / Objective

Aurora Finance's asset management desk needs to allocate equity capital across 6 large-cap Indian stocks. The objective is to:

1. **Deliverable 1 — Return Ranking:** Predict annualised forward returns (1-year and 3-year) for each stock and generate BUY/SELL signals vs the Indian risk-free rate (6.5% p.a.).
2. **Deliverable 2 — Portfolio Optimisation:** Build a Max-Sharpe portfolio from stocks with predicted positive excess returns. Fall back to cash (risk-free) if none qualify.
3. **Deliverable 3 — Backtest:** Validate the strategy over the most recent 2-year window against a cash benchmark.

---

## 3.2 Dataset Description

| Attribute | Details |
|---|---|
| **Source file** | `sample_data/Market_Data_Revised.xlsx` |
| **Stocks** | Asian Paints, Cipla, HDFC Bank, ITC, TCS, UltraTech Cement |
| **Date range** | January 2005 — February 2026 (~21 years) |
| **Rows per stock** | ~5,247 trading days |
| **Stock columns** | `date`, `company_name`, `closing`, `high`, `low`, `trade Volume`, `Return` |
| **Macro sheets** | `Macroeconomic_QRT` — quarterly GDP growth & inflation; `Macroeconomic_Annual` — annual GDP growth & inflation |

---

## 3.3 Methodology / Approach

### Dual-Horizon Ensemble Framework

```
For each stock × each horizon (1Y and 3Y):
  ┌─────────────────────────────────────────────┐
  │  Rolling-Window CV (14 folds)               │
  │  Train: 5yr  │  Embargo: = horizon  │ Test: 1yr│
  └──────────────────┬──────────────────────────┘
                     │
         XGBoost + LightGBM + Random Forest
                     │
         Softmax blending (weights from CV hit rate)
                     │
         Live inference on most recent data point
                     │
         Annualised predicted return → BUY/SELL vs 6.5%
```

### Portfolio Optimisation

- **Confidence shrinkage:** Predicted returns scaled by `clip((hit_rate − 0.50) / 0.10, 0, 1)` — a model with 50% accuracy (random) contributes nothing; one with 60% contributes 100%.
- **Max-Sharpe (SLSQP):** SLSQP optimiser maximises `(port_return − RF_RATE) / port_volatility` subject to weight bounds [5%, 40%] and sum-to-1 constraint.
- **Blending:** 50% tactical weight (1Y optimised) + 50% strategic weight (3Y optimised).
- **Cash gate:** If no stock has adjusted predicted return > 0, the portfolio holds 100% risk-free assets.

---

## 3.4 Data Preprocessing Steps

| Step | Details |
|---|---|
| **Macro alignment** | QRT and Annual data forward-filled to daily frequency; joined to each stock on date |
| **All features shifted by 1 day** | Prevents lookahead bias — only yesterday's data informs today's prediction |
| **Infinity handling** | `replace([inf, -inf], NaN)` — eliminates divide-by-zero (e.g., zero volume days) |
| **Forward return targets** | `fwd_ret_1y = cumulative 252-day product of (1 + Return)` shifted by -252 |
| **Live tail preservation** | Last 252 (1Y) / 756 (3Y) rows intentionally have NaN targets — the future hasn't happened; these rows are preserved for live inference |
| **Embargo** | Gap between training and test = horizon length (252 or 756 days) to prevent forward-return leakage |

### Features (20 total)

| Group | Features |
|---|---|
| Short-horizon (9) | ret_1, ret_5, ret_20, vol_5, vol_20, mom_5, mom_20, vol_ratio, price_range |
| Long-horizon (7) | mom_252, mom_756, price_vs_ma252, price_vs_ma756, vol_252, vol_ratio_sr_lr, vol_ratio_252 |
| Macroeconomic (4) | macro_gdp_qrt, macro_inflation_qrt, macro_gdp_ann, macro_inflation_ann |

---

### Ensemble Models

| Model | Key Parameters |
|---|---|
| XGBoost | 200 trees, lr=0.05, max_depth=3, subsample=0.8, L1=0.1, L2=1.0 |

| Parameter | Value |

| Embargo | = horizon (252 for 1Y, 756 for 3Y) |
| Folds (1Y) | 13 |

### Blend Weights (Softmax)

Each model's blend weight is determined by its average CV hit rate (directional accuracy — did it correctly predict BUY vs SELL?), converted via softmax with temperature=0.1. This concentrates weight on the highest-performing model per stock.

# Module 4 — Derivatives: NIFTY Options Pricing

**Notebook:** `Step4_derivatives_module.ipynb`

---

## 4.1 Problem Statement / Objective

Aurora Finance's derivatives desk needs to price NIFTY 50 options accurately. The Black-Scholes (BS) model is the industry standard, but it makes assumptions (constant volatility, lognormal returns, single risk-free rate) that cause systematic mispricing — especially for near-expiry weekly contracts and options away from the money.

**Objectives:**
1. Build a **Hybrid Model** that uses Black-Scholes as a base price and trains XGBoost to predict and correct the BS pricing residual.
2. Compare the hybrid model's accuracy against standalone Black-Scholes.
3. Analyse implied volatility skew and sources of BS mispricing.
4. Validate out-of-sample performance using walk-forward validation.

---

## 4.2 Dataset Description

| Attribute | Details |
|---|---|
| **Source file** | `sample_data/Option_Chain_NSE_intraday_NIFTY_2Feb24.xlsx` |
| **Date** | 2 February 2024 (intraday, NSE) |
| **Index** | NIFTY 50 |
| **Rows (post-filtering)** | 6,408 option records |
| **Key columns** | `Time`, `Expiry`, `Spot`, `Strike`, `Call IV`, `Put IV`, `Call LTP`, `Put LTP`, `Call Bid/Ask`, `Put Bid/Ask`, `Call_Traded_Qty`, `Put_Traded_Qty` |
| **Expiries covered** | 6 expiries: 8-Feb, 15-Feb, 22-Feb, 29-Feb, 7-Mar, 28-Mar 2024 |

---

## 4.3 Methodology / Approach

### Hybrid Architecture

```
Input (Spot, Strike, IV, TimeToExpiry, r_eff) 
              ↓
   Black-Scholes Base Price
              ↓
       BS Residual = Market LTP − BS Price
              ↓
   XGBoost learns to predict the residual
              ↓
   Final Prediction = BS Price + XGB Residual
```

This hybrid approach leverages BS's financial structure while letting XGBoost capture what BS cannot: volatility smile/skew, liquidity effects, and microstructure noise.

### Walk-Forward Validation

- The intraday dataset is ordered by timestamp.
- The first 50% of timestamps form the initial training set.
- Test windows of 10% are rolled forward one step at a time.
- **Temporal integrity asserted:** Each test window's start timestamp must be strictly after the training window's end — enforced via `assert` at each fold.
- No shuffling; no data from the future is used in training.

### Per-Expiry Risk-Free Rate (Critical Fix)

The standard 7% T-bill rate produced systematic mispricing of ₹15–40 on near-expiry contracts because NSE's BS formula uses the implied cost of carry `r_eff = r − q`, where `q` is the dividend yield absorbed into the futures premium.

**Per-expiry `r_eff` backed out from put-call parity on 2-Feb-2024:**

| Expiry | r_eff |
|---|---|
| 8-Feb (weekly) | 14.4% |
| 15-Feb | 9.3% |
| 22-Feb | 7.2% |
| 29-Feb (monthly) | 6.8% |
| 7-Mar | 7.4% |
| 28-Mar | 7.3% |

The 8-Feb weekly contract's `r_eff` of 14.4% (vs the 7% T-bill) is caused by the high cost of carry embedded in the near-term futures premium.

---

## 4.4 Data Preprocessing Steps

| Step | Details |
|---|---|
| **Timestamp parsing** | `pd.to_datetime`; data sorted chronologically |
| **Null/zero removal** | Rows with zero Spot, Strike, IV, or LTP dropped |
| **ATM filtering** | Moneyness = Spot/Strike kept in [0.90, 1.10] — removes deep OTM/ITM options with wide spreads |
| **TimeToExpiry** | `(Expiry − Time).total_seconds() / (365.25 × 24 × 3600)` — includes intraday hours for precision |
| **Bid-Ask Spread** | `Call Ask − Call Bid`; `Put Ask − Put Bid` — proxy for liquidity |
| **IV conversion** | `Call IV / 100` → decimal form |
| **Cyclical time encoding** | `Hour_sin/cos`, `Minute_sin/cos` — encodes intraday time without treating it as linear |
| **Per-expiry risk-free rate** | Expiry key mapped to `r_eff_by_expiry` dict; fallback to 7% for unknown expiries |

Standard BS formula implemented with:

- Degenerate input guards (sigma < 1e-6, T < 1e-6 are clipped with warnings)
- Vectorised branching for call/put selection

## 4.6 Results and Observations

### Hybrid Model Performance (Walk-Forward, Out-of-Sample)

### Black-Scholes Comparison

Before the per-expiry `r_eff` fix:
- BS systematically **underpriced calls** and **overpriced puts** by ₹15–40 on the 8-Feb weekly contract due to the incorrect 7% flat rate.

After the per-expiry `r_eff` fix:
- Residual BS errors reflect genuine market effects — volatility skew, liquidity premium, non-lognormal tails — which XGBoost learns to capture.

### Implied Volatility Skew

- Put IV > Call IV across most strike levels — the classic "volatility smirk" pattern observed in equity indices (left tail risk premium).
- IV is highest for near-expiry strikes close to the money, and declines for longer-dated contracts.

### Feature Importance

Top features for both call and put models:
1. `Call_IV_Decimal` / `Put_IV_Decimal` — IV is the dominant pricing signal (as expected)
2. `TimeToExpiry` — theta decay effect
3. `Moneyness` — distance from the money
4. `Spread_Call/Put` — liquidity proxy
5. `Call/Put_Traded_Qty` — demand-side signal

Cyclical time features (`Hour_sin/cos`) contribute — intraday option pricing varies with market open/close dynamics.

# Overall Conclusion & Future Scope

## Cross-Module Summary

This project demonstrates end-to-end ML pipeline design across four distinct financial domains:

| Module | Core ML Insight |
|---|---|
| Corporate Finance | Small datasets require disciplined feature engineering (ratio ≤ 1:10) and LOOCV. Ridge regression is the safer bet over complex models when n < 100. |
| Banking | Combining supervised (PD regression) and unsupervised (Isolation Forest) approaches captures both structured credit risk and unstructured fraud patterns. F2-score threshold optimisation aligns the model with business consequences. |
| Financial Markets | Directional accuracy (hit rate) matters more than R² for trading signals. Embargo-based CV is non-negotiable for long-horizon targets — without it, CV results are optimistically biased. |
| Derivatives | Hybrid models (theory + ML residual correction) outperform either approach alone. Domain-aware preprocessing (per-expiry carry rates) eliminates structural bias before any ML is applied. |

## Common Themes Across All Modules

1. **Leakage prevention is paramount.** Every module uses temporal or fold-based techniques to prevent the model from seeing the future: LOOCV, embargo gaps, walk-forward splits, and time-based train/test ordering.
2. **Domain knowledge before data.** Features are constructed from financial theory first (NPV, IRR, PD, moneyness, cost of carry) — ML then enhances what theory provides, rather than replacing it.
3. **Evaluation metrics match business goals.** MAE for cashflow (dollar error), F2-score for fraud (recall-heavy), hit rate for trading signals (direction matters), R² + RMSE for option pricing (magnitude precision).
4. **Interpretability alongside accuracy.** SHAP values (Module 1), weighted risk scores (Module 2), CV hit rates by stock (Module 3), and feature importance by fold (Module 4) all provide the "why" alongside the prediction.
